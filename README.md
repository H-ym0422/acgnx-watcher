# ACGNX Watcher · 新番资源更新提醒

通过 ACGNX RSS 检查动画资源更新，按番名、季度、集数和字幕组筛选，将发布信息与资源链接推送到飞书等通知渠道。

日常操作可以直接在 GitHub Issue 标题里写一句话。配置好云端运行后，电脑关机也能继续检查。

[开始使用](#开始使用) · [自然语言操作](#自然语言操作) · [字幕组与等待期](#字幕组与等待期) · [部署与运行](#部署与运行) · [常见问题](#常见问题)

## 能做什么

- **查找资源**：一次查询指定季度、单集、集数区间或指定字幕组，在 Issue 内返回结果。
- **持续追番**：保存监听规则，后续检查新发布、修正版及字幕形式升级。
- **指定字幕组优先**：其他组先发布时逐集等待 7 天，也可关闭其他组兜底。
- **手机管理**：通过 Issue 添加、暂停、恢复、修改、删除规则和查看追番列表。
- **历史回溯**：添加时选择全部历史、最新一集或跳过历史资源。
- **持久状态**：保存去重记录、等待起点和待重试消息；跟踪整体及每部番的抓取状态。

项目负责查询和通知，不负责自动下载、播放或制作字幕。资源范围取决于 RSS 返回内容，不是完整的历史资源库。

## 开始使用

### 已经部署好了

1. 在自己的仓库打开 **Issues → New issue**。
2. 选择 **自然语言请求**，把完整要求写在标题，正文可以留空。
3. 提交后等待机器人评论，先核对回复开头的识别结果。
4. 持续追番后，可打开自动生成的 [我的番剧.md](我的番剧.md) 查看规则、检查状态和推送记录。

只查询一次：

```text
给我找药屋少女的呢喃第三季第三集之后的资源，字幕组为喵萌奶茶屋
```

持续追番：

```text
帮我追药屋少女的呢喃第三季，从第三集起，字幕组为喵萌奶茶屋
```

**“给我找”只在 Issue 回复资源，不新增订阅、不修改推送历史、不发送飞书通知；“帮我追”才保存长期规则。**

以上番名、季号和集数仅为操作示例，不表示当前一定存在对应资源。首次部署请先完成下方的[部署与运行](#部署与运行)。

## 自然语言操作

### 查询与追番

| 想做什么 | Issue 标题示例 |
|---|---|
| 查某季第 3 集及以后 | 给我找药屋少女的呢喃第三季第三集之后的资源，字幕组为喵萌奶茶屋 |
| 只查第 3 集 | 给我找药屋少女的呢喃第三季第三集的资源，字幕组为喵萌奶茶屋 |
| 查第 3 至 5 集 | 给我找药屋少女的呢喃第三季第三至第五集的资源 |
| 从第 3 集起持续追番 | 帮我追药屋少女的呢喃第三季，从第三集起，字幕组为喵萌奶茶屋 |
| 添加时只回溯最新一集 | 帮我追示例动画，只推最新一集，字幕组为喵萌奶茶屋 |
| 跳过旧集，只追后续更新 | 帮我追示例动画，不补旧集，字幕组为喵萌奶茶屋 |
| 只接受指定字幕组 | 帮我追示例动画，字幕组为喵萌奶茶屋，不兜底 |

- 中文数字和阿拉伯数字均可使用；条件之间建议用逗号分隔。
- **“第三集之后”“从第三集起”均包含第 3 集。** 不含第 3 集时，请写“从第四集起”。
- 单集和固定区间目前用于查询；持续追番请写“从第 N 集起”。
- 查询未写字幕组时不限定组；追番未写字幕组时先列选组清单，可回复原清单序号、完整组名或“任意”。
- 追番未指定回溯方式时，沿用 `all`，处理起始集数范围内可获取的历史资源；其他组历史同样遵守等待期。
- 合集按集数范围交集返回，可能包含请求范围外的集数；最多展示 20 条查询结果。

### 管理已有规则

追番列表只展示番名、季度和字幕组，内部规则编号由删除链接自动传递。除删除操作外，完成的加番、查询、列表和管理操作自动归档到已关闭 Issues；等待选组或执行失败的 Issue 保持打开。删除成功后，对应行会从“我的番剧.md”移除。


推荐打开 [我的番剧.md](我的番剧.md)，在对应番剧行点击 **删除**，核对番名、季度和字幕组，勾选确认后提交。页面会自动带入唯一规则 ID，无须手写名称；提交前不会删除。每行只对应一条规则，同名番剧的其他字幕组规则保留。

GitHub Markdown 文档不能运行弹窗脚本，因此这里使用“删除入口 → 确认页复选框 → 提交”的方式。规则在打开确认页后若有变化，会要求刷新列表重新确认。


| 操作 | Issue 标题示例 |
|---|---|
| 查看追番列表 | 我的追番列表 |
| 暂停 | 帮我暂停药屋少女的呢喃第三季 |
| 恢复 | 帮我恢复药屋少女的呢喃第三季 |
| 删除 | 帮我删除药屋少女的呢喃第三季 |
| 修改字幕组 | 帮我把药屋少女的呢喃第三季的字幕组改为喵萌奶茶屋 |
| 使用唯一 ID 定位 | 帮我暂停 r-xxxxxxxx |

每个 Issue 只执行一个操作。管理操作请新建 Issue，不要靠编辑旧标题或追加评论再次执行。匹配到多条规则时会拒绝操作，请查看配置中的唯一规则 ID。

暂停会保留去重历史并取消该规则的待发送消息；恢复沿用历史。删除会清理该规则及相关状态；当前 Webhook 渠道不会自动撤回已经送达的飞书消息。

暂不支持在自然语言标题中设置“字幕格式为……”筛选条件，遇到这类条件会明确拒绝，不会保存为番名。可先查看逐集字幕类型，再选择字幕组。

自然语言入口使用本地规则解析常见中文表达，无须额外模型或 API 密钥；不保证理解任意长句。标题与正文条件冲突时会拒绝修改，查询条件请完整写在标题中。

## 推送标题

| 消息 | 标题示例 |
|---|---|
| 新集资源 | 【新番速递】学生会有洞（喵萌奶茶屋） |
| 更优版本 | 【资源更新】（更优版本）学生会有洞（喵萌奶茶屋） |
| 修正版 | 【资源更新】（修正版）学生会有洞（喵萌奶茶屋） |
| 抓取异常或恢复 | 【运行提醒】抓取异常 / 【运行提醒】抓取恢复 |

整体、单部番及合并的抓取状态提醒统一使用“运行提醒”；更优版本和修正版统一使用“资源更新”。`settings.title_prefix` 继续用于普通新集资源。这里只调整标题，不改变资源筛选、等待期或推送时机。

## 每集字幕类型

选组清单会在每个字幕组下按集数列出可选字幕形式；加番历史消息则汇总实际选中的资源，并在每条磁力旁再次标注。

```text
01 简繁日内封
02 简日内嵌

01~10 简日双语
01、03、05、10、22 简繁内封
01~03、05、08~10 简日双语
```

只合并同一字幕组、同一字幕类型的连续集号，不把缺集填成连续范围。同一集存在多种发布版本时，选组清单会分别列出；未标注字幕的资源明确提示“未标注，请查看发布说明”。标签依据发布标题，不对下载后的实际字幕内容作推断。

## 字幕组与等待期

设置指定字幕组并开启兜底后，其他组先发布某一集，**不会立即触发兜底推送**：

1. 首次观察到该集其他组资源，记录等待起点和候选资源。
2. 等待完整 **7 天（168 小时）**，每条规则、每一集独立计时。
3. 期间发现指定组发布，或已有覆盖该集的指定组历史记录，取消该集普通兜底。
4. 等满 7 天仍未发现指定组，且符合当前规则时，才允许选择一份其他组资源补发。若季度待确认，相关兜底会暂缓。

计时依据是**机器人首次观察时间**，不是资源标注的发布日期；重启不会重置计时。升级前尚无等待记录的资源，从升级后首次观察开始计时。

等待到期不表示字幕组停更；指定组后来发布仍可提醒。多个指定组可分别推送同一集，修正版和字幕形式升级也可能产生新提醒。

不希望接收任何其他组资源时，在追番标题末尾加 `，不兜底`。未限定字幕组的规则不需要等待。

## 季度、集数和历史回溯

| 设置 | 含义 |
|---|---|
| 季号 | 限定某一季；不凭每季固定 12/24 集推算 |
| 起始集数 | 对后续检查和待重试单集持续生效 |
| `all` | 添加时回溯可获取且符合条件的历史资源，默认方式 |
| `latest` | 添加时只回溯最新一集，随后继续监听 |
| `none` | 跳过历史资源，仍可发送加番确认，随后继续监听 |

历史回溯同样遵守指定组优先和 7 天等待期。`none` 不会在一周后补发原本跳过的历史，`latest` 也不会变成延迟发送全部历史。修改规则不会自动重新推送全部历史。

季度优先使用标题明确标注，也支持本番明确的季内／累计编号证据，例如 `03(51)`。信息不足时会显示 `needs_confirmation`，保守排除或暂缓相关资源。

必要时可通过原表单或配置明确本季累计起点 `season_start_episode`，或显式允许未标季度 `allow_unmarked_season`。后者存在混季风险，具体写法见 [使用说明](docs/usage.md)。

## 部署与运行

### 云端运行：GitHub Actions

适合电脑不常开、希望用手机管理的场景。工作流在云端抓取、筛选、推送，并将状态提交回仓库。

首次独立部署：

1. 将源码放入自己的仓库，以 [config.example.json](config.example.json) 为配置参考，换成自己的规则。不要直接复用他人的监听配置和推送历史。
2. 启用仓库 Actions，并确认工作流能向主分支写入状态；当前工作流以 `main` 为运行分支。
3. 在 **Settings → Secrets and variables → Actions** 添加所用通知渠道的密钥。飞书群机器人使用下表前两项。
4. 在 **Actions → ACGNX Watcher → Run workflow** 勾选测试选项，发送一条演示消息验证通知通路；不勾选则执行一轮检测。
5. 确认运行和状态保存成功后，再通过 Issue 添加自己的追番。
6. 如需 Cloudflare 定时触发，按 [Worker 部署说明](cloudflare-cron/README.md) 配置自己的 Worker。仓库也保留 GitHub 原生定时入口。

已有部署升级时，**保留自己的 `config.json`、`state.json` 和有效备份**，更新程序即可。不要用示例或别人的状态覆盖现有历史。

定时目标为每 5 分钟检查一次，实际执行受调度、队列、网络和平台额度影响，不保证准点。已有 Worker 可继续使用；不要为同一部署额外重复配置多个定时器。

### 通知渠道

| 渠道 | GitHub Secret 名称 | 配置提示 |
|---|---|---|
| 飞书／企业微信／钉钉群机器人 | `ACGNX_WEBHOOK_URL` | 配置 `settings.push_channel = "webhook"` |
| 飞书群机器人签名校验 | `ACGNX_FEISHU_SECRET` | 机器人开启签名校验时填写 |
| 钉钉加签 | `ACGNX_DINGTALK_SECRET` | 机器人开启加签时填写；关键词对应 `dingtalk_keyword` |
| PushPlus | `PUSHPLUS_TOKEN` | 配置渠道为 `pushplus`，或使用 `auto` |
| Server酱 | `SERVERCHAN_SENDKEY` | 配置渠道为 `serverchan`，或使用 `auto` |

代码也支持飞书自建应用私聊，需 `ACGNX_FEISHU_APP_ID`、`ACGNX_FEISHU_APP_SECRET` 和 `ACGNX_FEISHU_CHAT_ID`；涉及应用权限和接收会话配置，使用前应核对对应工作流的环境变量传递。日常飞书群通知可直接使用 Webhook。

Secret 用于保存地址、Token 和签名密钥，不要把这些值写进 README、截图或公开配置。各渠道的额度、权限和收费以服务实际规则为准。

### 本地运行：Windows / Linux / macOS

建议 Python 3.12，运行程序只依赖 Python 标准库。打开终端，切换到包含 `acgnx_watch.py` 的源码目录。

首次独立部署、目录中尚无个人配置时，可复制示例：

```powershell
Copy-Item config.example.json config.json
```

修改 `config.json`，换成自己的规则。已有配置时跳过复制，避免覆盖。飞书 Webhook 可通过 PowerShell 环境变量传入，仅对当前终端会话生效：

```powershell
$env:ACGNX_WEBHOOK_URL = "你的飞书机器人 Webhook 地址"
# 开启签名校验时再设置：
$env:ACGNX_FEISHU_SECRET = "你的签名密钥"
```

常用命令：

```bash
# 验证配置
python add_rule.py --validate

# 试跑一轮：打印命中，不发送通知、不修改去重状态
python acgnx_watch.py --once --dry-run

# 实际执行一轮
python acgnx_watch.py --once

# 持续运行，Ctrl+C 停止
python acgnx_watch.py
```

如果电脑只安装了 Python 启动器，可将 `python` 换成 `py`。本地监听需要电脑开机且程序保持运行；本地配置修改也需要同步到仓库才会影响云端。

## 状态与排查

| 文件或入口 | 用途 |
|---|---|
| [我的番剧.md](我的番剧.md) | 自动生成的规则列表、抓取状态、推送记录和待确认信息 |
| `config.json` | 自己的规则与运行设置 |
| `state.json` | 去重历史、等待起点、通知队列和运行状态 |
| `state.backup.json` | 状态备份，主状态异常时用于恢复 |
| `logs/watcher.log` | 本地运行日志 |
| GitHub Actions 运行日志 | 云端抓取、解析、推送及状态保存结果 |

“已记录到”是去重基线，不代表每条历史消息都已送达；“最近成功推送”与去重历史分别展示，搜索最大集号也不等于全季总集数。

程序会过滤明确的漫画、小说、电子书等非动画资源，跟踪每部番连续抓取故障及恢复；有效空 RSS 与网络失败分别处理。网站整体故障只发送一条总提醒，恢复时也只发送一条；同轮多部番的独立故障或恢复合并通知，部分恢复会列出仍异常的番剧。

## 静默删除与记录清理

删除追番不发送飞书确认消息；成功删除后也不追加 Issue 成功评论。追番列表仍会自动移除对应行。

若要同时永久清除该删除 Issue，需要在仓库 Actions Secrets 设置 `ACGNX_ISSUE_DELETE_TOKEN`，使用仓库所有者身份的令牌。公开仓库可使用 classic 令牌的 `public_repo` 权限；该权限覆盖账号可访问的公开仓库，不能限定为单个仓库，不要误选整个 `repo` 或 `delete_repo`。个人仓库的 Issue 永久删除仅所有者可执行，普通工作流令牌不能替代所有者身份。此操作不可恢复。

缺少该令牌、令牌无权删除或接口失败时，规则删除仍然有效，删除 Issue 会静默关闭保留，原因记录在 Actions 日志，不发送额外提醒。

当前使用飞书群机器人 Webhook，仅具备推送能力，项目没有启用自动撤回，也没有部署飞书界面自动化。群主或管理员可在客户端按平台权限和撤回时限处理旧消息；本地“删除”与群内“撤回”不同。若以后改用应用消息，需要另行接入应用或用户授权、保存消息 ID，并遵守管理员设置的撤回时限；新应用机器人不能直接撤回旧 Webhook 机器人的消息。

本仓库于 2026-10-19 已验证所有者令牌并永久清理 61 条历史操作 Issue，仅留下三条“追番｜番名”记录。它们是本次整理时建立的入口，不是实时订阅数据库；最新规则、状态与删除入口始终以 [我的番剧.md](我的番剧.md) 为准。后续新增、查询等操作仍按各自流程归档，永久清理不会定期扫描所有 Issues。

配置步骤见 [使用说明](docs/usage.md#配置永久清理令牌)，清理失败的排查见 [恢复说明](docs/recovery.md#issue-永久清理失败)。

## 常见问题

**为什么查不到？**  
RSS 搜索只覆盖近期资源，关键词或译名差异、季度缺失、字幕组尚未发布都可能影响结果。先核对机器人识别摘要，换更明确的番名，并查看是否提示“季度待确认”。0 条结果不代表字幕组停更。

**为什么别的组已经出新一集，我还没收到？**  
指定组优先时，其他组资源逐集等待 7 天；尚在等待期、季度待确认或消息仍在队列中，都可能暂未推送。

**为什么还会收到同一集？**  
可能来自另一个指定组、指定组晚于兜底发布、修正版或字幕形式升级，也可能是失败重试。请结合标题、字幕组、版本和 Actions 日志判断。极端中断时仍存在重复窗口，不要通过删除状态文件解决。

**网站能打开，为什么提示搜索异常？**  
网页、最新资源 RSS 和关键词搜索是不同入口。程序优先使用 `/rss.xml?keyword=…`，无有效 RSS 时尝试其他镜像及旧搜索路径。最新流可用但搜索失败时仍可能漏抓，查询、选组和历史补抓也会受影响；告警会说明最新流是否可用。有效空搜索与网络/接口失败分别处理，搜索失败不能解释为字幕组没有更新。

**为什么 Issue 没有执行？**
只有仓库所有者的操作会执行。检查 Actions 是否启用、对应任务是否排队或失败、规则是否匹配多条，以及是否把新操作写在了旧 Issue 中。管理操作请新建 Issue。

**机器人说处理完成，但消息没到？**  
先看具体输出是否为“仅查询”或“待重试”，再检查通知通路、渠道选择、签名和限流。查询只回复 Issue；规则保存成功也不等于通知已经送达。

**可以保证绝不重复、绝不漏抓吗？**  
不能。RSS 窗口、标题格式、组名及季度证据均有限。云端在发送前保存远端队列、成功后保存收据，检查点失败会停止后续发送；但外部服务接收消息与远端收据提交并非原子事务。异常处理见 [恢复说明](docs/recovery.md)。
