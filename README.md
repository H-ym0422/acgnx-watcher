# ACGNX 新番监听

盯着[末日動漫資源庫](https://share.acgnx.se/)，一有你要的番就推到手机。

跑在 GitHub 的服务器上，跟你自己的电脑没关系。电脑关机、断网、没带出门都照样工作，
每 5 分钟检查一次，有新集就推一条带磁力链接的消息。

---

## 现在在追什么

看 [我的番剧.md](我的番剧.md)。有新集时它会自动更新。

想手动查一遍，就在 Issues 里新开一个，标题写 `列表`。

## 加番、删番

手机上打开 Issues，新建一个，标题写：

```
加番 咒术回战
```

**正文不用填。** 十几秒后机器人会在 Issue 里回一条评论，列出有哪些字幕组在做这部番、
各自都发过什么字幕类型：

```
搜到 12 个字幕组在做「咒术回战」。回复这条 Issue 告诉我要哪个：

 1  豌豆字幕组       · 23 条，最近 09-21
    类型：繁體、简繁外挂字幕、简体
 2  绿茶字幕组       · 14 条，最近 04-07
    类型：简日内嵌、简繁日内封
 3  风之圣殿字幕组    · 14 条，最近 04-05
    类型：简体、繁體
 4  LoliHouse      ·  7 条，最近 04-06
    类型：简繁外挂字幕
...
```

看清楚之后，在**同一条 Issue 下面回复**：

- `2` 或 `1,3` —— 按序号选
- `绿茶字幕组` —— 直接写组名也行
- `任意` —— 不挑组，谁先出就推谁

机器人收到回复才会真正加上，然后把第 1 集到最新集的磁力一次给你，
飞书同步收到通知。之后每出一集新集，自动再推一条。

**想跳过这一步**：在正文第一行直接写字幕组（多个用逗号隔开，比如 `绿茶字幕组,喵萌奶茶屋`），
它就不再问，直接加。

**删掉**：发一个标题是 `删番 咒术回战` 的 Issue。

**查列表**：发一个标题是 `列表` 的 Issue，或者直接看 [我的番剧.md](我的番剧.md)。

### 多季番：只想看某一季

比如《无职转生》今年出到第四季，你只想追第一季。用「加番」模板时，
**「第几季」填 1**，标题和字幕组照常填就行。

判定方式：标题里标了「第二季 / S2 / Ⅱ / 2nd Season」的会被丢掉，
**没标季号的算第一季**（大多数字幕组做第一季时压根不写「第一季」）。

> ⚠️ **但搜索只覆盖最近发布的条目。** 比如直接搜「无职转生」只能搜到当前在播的那季，
> 第一季的旧集根本不在结果里。想看老季，得靠**后来重发的 BD / 合集**：
> 把标题改成 `加番 无职转生 BD` 或 `加番 无职转生 合集`，一般能捞到。
> （实测：搜「无职转生」50 条全是第三季；搜「无职转生 BD」就有第一季的了。）

### 清单里的「覆盖」是什么意思

机器人回复的清单里，每个字幕组下面都有一行：

```
` 4`  **LoliHouse**  ·  8 条，最近 09-27
　　覆盖 第 01~12 集（12 集） · 类型 简繁内封字幕
```

**这就是这个组做到了第几集**，用来判断完不完整（有缺集会标「缺 03」）。
选组之前先看这行，别选了个从第 5 集才开始的。

### 另一个入口：Actions 页面（电脑上方便）

```
https://github.com/H-ym0422/acgnx-watcher/actions/workflows/add-rule.yml
```

打开后右边有 **Run workflow** 按钮。这里的行为分两种：

- **填了「字幕组」或者勾了「任意字幕组」** → 直接加，一步到位
- **什么都没填** → **不会替你瞎选**，而是自动开一条标题是 `加番 番名` 的 Issue，
  并把字幕组清单贴在 Issue 里。你在那条 Issue 下面回复序号才真正加上。

不管从哪个入口进来，「没选字幕组」最后都会汇到同一条 Issue 问答流程。

> ⚠️ GitHub 手机端经常不显示 `Run workflow` 按钮，手机上还是推荐直接发 Issue。

> 关于「类型」这一列：它是从发布标题的方括号里读出来的，各组的写法不统一，
> 所以有的显示成「简繁日内封」、有的显示成「简繁外挂字幕」。少数组干脆不标，
> 就显示「未标注字幕类型」—— 那种一般是生肉或者纯搬运。

两种备选方式：

- **Actions 页面**：进 `加番` 这个工作流，点 Run workflow 填番名。
  注意 GitHub 手机端经常不显示这个按钮，所以还是推荐发 Issue。
- **在电脑上**：进 `acgnx-cloud` 目录跑 `python add_rule.py 咒术回战`。
  好处是它会列出所有在做这部番的字幕组（带条数和更新时间）让你挑，比自动选准确。

## 收到的是什么样

```
【新番速递】已加入监听：金牌得主（爱恋字幕社/喵萌奶茶屋）

标题：【喵萌奶茶屋】★01月新番★[金牌得主 / Medalist][22][1080p][简日双语][招募翻译]
字幕组：爱恋字幕社 / 喵萌奶茶屋
字幕形式：简日双语
集数：第 22 集
大小：1.2GB
发布：2026-03-28 20:15
详情：https://share.acgnx.cc/show-xxxx.html
磁力：
magnet:?xt=urn:btih:xxxx&tr=...
```

**关于「字幕形式」这一行**：它是从发布标题里读出来的，各个组的写法不统一，
看到的有「简日双语」「简日内嵌」「简繁日内封」「简繁外挂字幕」「简中」这些。

**只要繁体字幕的版本不会推给你。** 判定方法是看形式里有没有「简」——
`繁日內嵌`、`繁體`、`CHT` 这类会被丢掉；`简繁日内封` 这种同时含简体的保留。
没标注形式的（生肉、搬运）不拦。想改这个行为，把 `config.json` 里的
`skip_traditional_only` 设成 `false`。

## 什么情况会再推一次

同一集反复出现不会重复打扰，但这几种会主动推：

- **这一集出了修正版** —— `[01v2]`、`[修正版]`、`[REPACK]` 这些
- **出现了更好的字幕形式** —— 按 `variant_prefer` 的顺序比，比如之前只有
  「简日内嵌」，后来出了「简日双语」
- **完结后出了整集打包** —— `[01-12合集]`、`[14-22 修正合集]`、`全12话` 这些
  都识别成合集，跟单集分开记，所以不会因为"第 12 集推过了"就把合集漏掉

推修正版和合集时，标题前缀会标「（修正版）」或「（更优版本）」。

## 加番时推多少可以调

在电脑上跑向导时加一个参数：

- `--backfill all`（默认）第 1 集到最新集全都给
- `--backfill latest` 只给最新一集
- `--backfill none` 都不给，只记下来，之后出新集才提醒

网页上的 `加番` 工作流也有这个下拉框。

## 有几个我自己踩过的坑，写在这儿

**番名尽可能用有辨识度的两三个字。** 站内搜索是子串匹配，太短会搜出一堆无关的。
搜不到时飞书会发一条「加番失败」并提示你换写法，试试日文原名或罗马音。

**同一部番不同字幕组的集数范围差别很大。** 比如「咒术回战」有十七个字幕组在做，
但绿茶字幕组只从第 53 集开始。想从第一集追，就得先看清是哪个组从第一集就在做 ——
这也是推荐用电脑上的向导的原因，它会先把每个组的条数列给你看。

**主域名 share.acgnx.se 在国内被 DNS 污染了**（解析到 Facebook 的 IP），直连必然超时。
脚本用的是官方镜像 `share.acgnx.cc`，走 Cloudflare，国内可以直连，不需要挂代理。

**网页版有 Cloudflare 反爬挑战，RSS 接口没有。** 所以脚本全部走 RSS：

- 最新发布 `/rss.xml`，只覆盖最近约 12 小时
- 关键词搜索 `/topics/rss/rss.xml?keyword=xxx`，覆盖该番整季

搜索接口偶尔会返回空结果，简繁也不通用（搜「学生会」得 0 条、搜「Seitokai」得 50 条）。
所以脚本内置了繁简转换，并且用「最新流 + 关键词搜索」双路抓取，空结果不当结论。

## 关于运行成本

GitHub Actions 对公开仓库不限分钟数，所以这个方案是零成本的。

如果把它改成私有仓库，免费额度只有 2000 分钟/月，而每 5 分钟跑一次大约需要
8640 分钟/月，会超支。要么保持公开，要么把频率降到 30 分钟一次。

已知限制：GitHub 的定时任务是「尽力而为」，高峰期会延迟几分钟到十几分钟；
仓库连续 60 天没有活动会暂停定时任务（不过每次有新集都会自动提交 state.json，不会触发这条）。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `acgnx_watch.py` | 主程序，负责抓取、去重、推送 |
| `add_rule.py` | 加番向导，也能生成 `我的番剧.md` |
| `config.json` | 监控规则。密钥字段是空的，走仓库 Secrets |
| `state.json` | 去重记录，**必须提交进仓库**，删掉会导致历史集数重推 |
| `我的番剧.md` | 自动生成的追番清单 |
|  `.github/workflows/watch.yml` | 每 5 分钟的定时检查 |
| `.github/workflows/add-rule.yml` | Actions 页面手动加番 |
| `.github/workflows/issue-rule.yml` | 发 Issue 加番 / 删番 / 查列表 |

## 如果哪天要重装

1. 建一个**公开**空仓库（不勾 README、gitignore、license）。
2. 把本目录所有文件传上去，包括 `.github` 和 `state.json`。
3. 仓库 Settings → Secrets and variables → Actions → New repository secret。
   Name 填 `ACGNX_WEBHOOK_URL`，Value 填飞书机器人的 Webhook 地址。

Secret 是给工作流用的，`config.json` 里不要填任何密钥 —— 这个仓库是公开的。

## 本地那份

本机 `acgnx-watcher` 目录里还有一份独立的工具（含本机版启动脚本和更详细的文档）。
它的 `config.json` 跟这份不会自动同步，本机开机自启也已经关掉了。日常用云端这份就行。
