# ACGNX Watcher · 新番发布提醒

按番名、字幕组和季号检查 ACGNX RSS，将新发布资源推送到飞书等通知渠道。
支持手机 Issue 管理、历史回溯、修正版/字幕形式升级提醒与去重；电脑关机也可由云端继续运行。

## 使用入口

在自己的仓库创建 Issue：

| 标题 | 操作 |
|---|---|
| `加番 番名` | 搜索字幕组，回复原清单序号或完整组名后添加 |
| `列表` | 查看追番、规则 ID 和检查/推送状态 |
| `暂停 规则ID` / `恢复 规则ID` | 保留历史记录地停用或恢复 |
| `修改 规则ID` | 修改字幕组、季号、起始集数 |
| `删番 规则ID` | 删除明确的规则 |

只接受仓库所有者操作，不处理 PR 评论。查看自动生成的 [我的番剧.md](我的番剧.md)。

添加正文可填写字幕组、季号、起始集数和历史范围；全部留空时先列清单，不替你选组。
历史范围支持 `all`、`latest`、`none`，默认保留原来的 `all`。
完整示例见 [使用说明](docs/usage.md)。

## 收到的消息

```text
【新番速递】示例动画
推送时间：2026年10月18日 12:00（北京时间）
标题：[示例字幕组] 示例动画 [03][简日双语]
字幕组：示例字幕组
字幕形式：简日双语
集数：第 03 集
详情：https://example.invalid/release
磁力：……
```

未知集数显示“暂未识别”；未标字幕形式提示查看发布说明。
清单中的去重基线与实际送达记录分别展示，不把搜索最大集号当作全季总集数。

## 运行方式

Cloudflare Worker 每五分钟触发 GitHub Actions，Actions 完成抓取、筛选、推送和状态提交。
也可在本地运行：

```bash
python add_rule.py --validate
python acgnx_watch.py --once --dry-run
python acgnx_watch.py --once
```

运行代码只需 Python 标准库。新部署从 [config.example.json](config.example.json) 开始；
已有项目保留自己的 config.json 和 state.json。
密钥通过环境变量或 GitHub Secrets 配置，不能提交进公开仓库。

部署步骤见 [开发与部署](docs/development.md) 和 [Worker 模板](cloudflare-cron/README.md)。
外部服务额度和调度延迟以其实际规则为准，不承诺准点或固定零成本。

## 可靠性与边界

- 相同关键词、季号、字幕组的重复添加被统一拦截，旧规则 ID 和历史保留。
- 指定组已有该集时不再推普通兜底；指定组后来补出仍可提醒。
- 其他组先发布时逐集等待 7 天；等待期间指定组发布则取消兜底，超时不认定停更。
- 回溯和普通单集均先保存待发送任务与基线，逐条确认送达后移除；失败保留原消息重试。
- 手动配置暂停或删除规则也会取消该规则的待发送消息；修改字幕组同步更新自动生成的规则名。
- 季度优先使用明确标注和本番累计／季内集号证据；无法确认时显示待确认，并暂缓相关兜底。可通过 Issue 配置本季累计起点或显式允许未标季度。
- 有效空 RSS、部分失败、全部失败分别记录；每部番独立跟踪连续故障与恢复，各提醒一次。
- 漫画、小说和电子书等明确非动画资源被排除；合集覆盖和累计集号统一参与去重与等待。
- 云端发送前提交远端队列，成功后提交收据；单轮最多尝试 12 条，超预算的消息下轮继续。
- 主状态损坏时尝试有效备份；都损坏则停止。旧格式读入迁移后保留基线。
- 查看/试跑不修改状态；试跑也不执行待发送队列。

RSS 搜索结果有限，标题和组名不统一，仍可能漏抓或误匹配。
远端检查点失败会停止后续发送，但服务接收消息到远端收据保存之间仍有重复窗口，无法承诺绝不重复。
异常处理见 [恢复说明](docs/recovery.md)，不要直接删状态文件来处理重复提醒。
