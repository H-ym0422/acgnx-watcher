# ACGNX 新番监听

盯着 [末日動漫資源庫](https://share.acgnx.cc/)，一有你要的番就推到手机。

**跟你的电脑没关系。** 电脑关机、断网、没带出门都照样工作，每 5 分钟检查一次。

---

## 它长什么样

```
Cloudflare Worker（每 5 分钟叫醒）
        ↓
GitHub Actions 抓取 → 判定 → 推送
        ↓
飞书 → 你的手机
```

### 为什么定时器不在 GitHub 上

本来写的是 GitHub 自带的 `schedule`，但**它对新建仓库的高频任务会降级** ——
实测请求每小时 12 次，实际投放约每 4 小时一次，有时候干脆一次都不跑。

所以定时器换成了 **Cloudflare Worker**（[`cloudflare-cron/`](cloudflare-cron/README.md) 目录），
它直接调 GitHub 的 `workflow_dispatch` 接口，绕开那个调度队列，实测准点。
GitHub 里那个 `schedule` 仍然留着，偶尔能跑一次算白捡的。

## 你手机上怎么用

打开仓库的 **Issues**，新开一个，标题写命令：

| 命令 | 等价说法 | 作用 |
|---|---|---|
| `加番 XXX` | `添加 XXX` / `新增 XXX` | 加一部番 |
| `删番 XXX` | `删除 XXX` / `移除 XXX` | 删一部番 |
| `列表` | `清单` / `我的番` | 看你现在在追什么 |

完整说明在 [我的番剧.md](我的番剧.md) —— 那份会自动刷新，加番的三个输入框怎么填也在里面。

### 加番时正文能填什么

用「新建议题」按钮新建时，有三个**可选**输入框：

| 输入框 | 什么时候填 | 例子 |
|---|---|---|
| **字幕组** | 只想看某个组做的 | `喵萌奶茶屋` |
| **第几季** | 多季番只追某一季 | `3` |
| **只要第几集之后** | **本地已经有前面几集了** | `49` |

**三个都留空也行** —— 机器人会先列清单，你在同一条 Issue 下回复序号或组名才真正加上。

### 加一部番（两步）

**第一步**：标题写 `加番 咒术回战`，**正文留空**。十几秒后机器人回复一份清单：

```
搜到 **12** 个字幕组在做「咒术回战」。回复这条 Issue 告诉我要哪个：

` 1`  **喵萌奶茶屋**  ·  17 条，最近 10-14
　　覆盖 第 03~08 集（6 集） · 类型 简日内嵌、简繁日内封
` 2`  **千夏字幕組**  ·  3 条，最近 05-11
　　覆盖 第 29~38 集（10 集） · 类型 繁體、简体、简繁内封
` 3`  **北宇治字幕组**  ·  6 条，最近 04-29
　　覆盖 第 37~38 集（2 集）· 缺 05、06 · 类型 简繁日内封、繁日內嵌
...
```

**第二步**：看清楚之后，在**同一条 Issue 下面回复**：

- `2` 或 `1,3` —— 按序号选
- `喵萌奶茶屋` —— 直接写组名也行
- `任意` —— 不挑组，谁先出就推谁

机器人收到回复才会真正加上，然后把符合条件的集数磁力一次给你，飞书也会收到。
之后每出一集新集，自动再推一条。

### 「覆盖」这一行要重点看

那是**这个组做到了第几集**，用来判断完不完整：

```
　　覆盖 第 03~08 集（6 集） · 类型 简日内嵌
　　覆盖 第 37~38 集（2 集）· 缺 05、06 · 类型 简繁日内封
```

标了「缺 05、06」说明它跳过了几集。**别选了个从第 30 集才开始的组却以为是全集。**

### 想跳过第一步

在正文第一行直接写字幕组（多个用逗号隔开），它就不再问：

```
加番 咒术回战

喵萌奶茶屋,千夏字幕組
```

用「加番」模板的话，正文的「字幕组」输入框填进去也一样。

### 已经有了前面几集？只要后面的

加番模板里有个 **「只要第几集之后」** 的输入框（可留空）。

比如《药屋少女的呢喃》第三季你本地已经有前 48 集了，就填 **49**：

```
加番 药屋少女的呢喃 第三季

喵萌奶茶屋
（只要第几集之后）49
```

- 只会推第 49 集及以后的
- **前面那些会记成「已看过」** —— 以后它们出修正版、或出了更好的字幕形式，**也不会再推你**
- **留空 = 从第 1 集开始**（跟以前一样）

命令行等价：`--from-episode 49`

> 判断依据是集数本身：单集 `48` 跳过、`49` 保留；
> 合集看它覆盖到的最大集号（`45-50` 这种有交集的会保留）；
> 认不出集数的条目一律保留 —— 宁可多给一条也不漏。

### 多季番只想看某一季

比如《无职转生》今年出到第四季，你只追第一季。

**先看番名** —— 如果标题里写了「第N季」，加番时会**自动认出**并只收那一季：

```
加番 药屋少女的呢喃 第三季     ← 标题里有「第三季」，会自动只收第 3 季
```

标题里没写季号时，才需要用「加番」模板的**「第几季」**输入框填数字。

判定方式：标题里标了别的季号（「第二季 / S2 / Ⅲ / 2nd Season」）的会被丢掉；
**标题里没标季号的会放行** —— 因为很多组做新季时压根不标季号
（实测喵萌的《药屋少女的呢喃》第三季 11 条正片，标题里一个季号都没有）。

> ⚠️ **但搜索只覆盖最近发布的条目。** 直接搜「无职转生」只能搜到当前在播的那季，
> 第一季旧集根本不在结果里。想看老季得靠**后来重发的 BD / 合集**：
> 标题改成 `加番 无职转生 BD` 或 `加番 无职转生 合集`。
> （实测：搜「无职转生」50 条全是第三季；搜「无职转生 BD」就有第一季的了。）

### 选了多个字幕组会怎样

选了 2 个组（比如「绿茶发布机 + 北宇治字幕组」），**两个组的资源都会给你**，
磁力后面会标上是哪个组做的：

```
[10] 北宇治字幕组  magnet:?xt=urn:btih:…
[10] 喵萌奶茶屋    magnet:?xt=urn:btih:…
```

如果某一集**只有别的组做了**，会用那个组并说明白：

```
字幕组：Nix-Raws
※ 第 51 集：「喵萌奶茶屋」还没出，这条用的是「Nix-Raws」做的
```

> 以前这句话写成「你指定的喵萌这一集还没出」，很容易被读成「整部番喵萌都没做」——
> 实际只是**那一集**。现在会写清是哪一集、用了谁。

**只有完全匹配不上的才会当替补**：一个组的全集包**不会**把另一个组的单集吃掉
（分组折叠只在同组内进行）。

### 音乐 / 原声条目不会混进来

站里常把主题曲、OP/ED、插曲原声跟正片混在同一部番下。
这些标题里没有集数，会被识别成「认不出集数的条目」推给你。
现在一律过滤：`主題歌 / 主题歌 / オープニング / エンディング / 插曲 / 原声 / OST / Drama CD` 等。

### 电脑上的另一个入口

```
https://github.com/H-ym0422/acgnx-watcher/actions/workflows/add-rule.yml
```

## 收到的是什么样

```
【新番速递】金牌得主（爱恋字幕社/喵萌奶茶屋）

推送时间：2026年10月16日 20:31（北京时间）

标题：[喵萌奶茶屋] 金牌得主 第2期 [22][1080p][简日双语]
字幕组：喵萌奶茶屋
字幕形式：简日双语
集数：第 22 集
大小：1.2GB
发布：2026-03-28 20:15
详情：https://share.acgnx.cc/announce/xxxx.html
磁力：
magnet:?xt=urn:btih:xxxx&tr=...
```

「字幕组」这一行显示的是**实际发布这个文件的组**。
如果你指定的组没做这一集，系统会自动换一个，并额外加一行说明：

```
字幕组：桜桃字幕组
※ 你指定的「喵萌奶茶屋 / 千夏字幕組」这一集还没出，这个是自动找的替补
```

### 字幕形式

从发布标题的方括号里读出来的，各组写法不统一：简日双语 / 简日内嵌 /
简繁日内封 / 简繁外挂字幕 / 繁體 / CHT ……没标的显示「未标注」。

**只要繁体的版本不会推给你**（`繁日內嵌`、`繁體`、`CHT` 这类会被丢掉；
`简繁日内封` 这种同时含简体的保留）。不标形式的（生肉、搬运）不拦。
想改这个行为，把 `config.json` 里的 `skip_traditional_only` 设成 `false`。

### 什么情况会再推一次

同一集反复出现不会重复打扰，但这几种会主动推：

- **出了修正版** —— `[01v2]`、`[修正版]`、`[REPACK]`
- **出现了更好的字幕形式** —— 按 `variant_prefer` 的顺序比
  （比如之前只有「简日内嵌」，后来出了「简日双语」）
- **完结后出了整集打包** —— `[01-12合集]`、`全12话` 会被识别成合集，
  跟单集**分开记**，所以不会因为「第 12 集推过了」就把合集漏掉
- **有全集包时不会再补一堆半截单集** —— 你有一个 `01-12` 全集包，
  机器人就不会再把 `05`、`06`…`12` 单独列一遍

推修正版和合集时，标题前缀会标「（修正版）」或「（更优版本）」。

### 推送失败会自动重试

飞书那边要是没发出去，**这一集不会被记成已看**，下一轮还会推。
所以推送失败不会漏片。

### 集数认不出来会怎样

标题格式是字幕组自己定的，**不可能 100% 都认得出**。系统现在的做法是：

| 情况 | 推送里怎么显示 |
|---|---|
| 认得出 | `集数：第 26 集` |
| 是整季/合集打包（**本来就没有**单一集数） | `集数：整季打包，没有单一集数（这条磁力是整季的）` |
| 认不出、又不是合集 | 同上 —— **不再显示一串哈希** |

所以认不出时磁力照样能用，只是你要知道「这条是整季的」。

**想看有哪些写法没覆盖**：

```
python add_rule.py --parse-report
```

它会列出所有「看着像正经单集、但集数没认出来」的标题和出现次数。
看到新写法告诉我，**补一条正则就能认出来** —— 这个记录是系统自动做的，
不用等你从推送里发现哪条不对。

> 字幕形式同理：标题里没标就写 `字幕形式：未标注（这个组没标，多半是生肉/原始片源）`，
> 不会再「有的有、有的没有」让你猜。

## 配置

### 加番时可调的参数

| 参数 | 网页上对应 | 说明 |
|---|---|---|
| `--backfill all`（默认） | — | 第 1 集到最新集全都给 |
| `--backfill latest` | 「推哪些」选 `latest` | 只给最新一集 |
| `--backfill none` | 选 `none` | 都不推，只记基线，之后出新集才提醒 |
| `--season N` | 「第几季」 | 多季番只追第 N 季（标题里有季号时会自动认） |
| `--from-episode N` | 「只要第几集之后」 | 本地已有前面几集时用 |
| `--no-fallback` | — | 只推你指定的字幕组（默认会用别的组补上他们没做的集数） |
| `--group X` / `--any-group` | 「字幕组」 | 指定字幕组，或不挑组 |

### 常改的 `config.json` 设置

| 字段 | 默认 | 说明 |
|---|---|---|
| `push_channel` | `webhook` | 推送渠道，见下 |
| `skip_traditional_only` | `true` | **只推简体的版本**。设成 `false` 连纯繁体也会推 |
| `watch_global_feed` | `true` | 走全站最新流（保证不漏）。关掉只靠关键词搜索 |
| `push_min_interval_seconds` | `13` | 连续补推时的间隔，避开平台频率限制 |
| `first_run_mode` | `latest` | 第一次跑时只推最新一集验证通路 |

改动直接编辑 `config.json` 提交即可，或者发 `列表` Issue 让机器人重新生成一次 `我的番剧.md`。

### 想换推送渠道

`config.json` 的 `push_channel`：

| 值 | 走哪个 |
|---|---|
| `webhook` | 群机器人（企业微信 / 钉钉 / 飞书），**当前用的** |
| `pushplus` | PushPlus（推到微信） |
| `serverchan` | Server酱（推到微信） |
| `auto` | 按上面顺序挑第一个配好的 |

> `feishu_app`（飞书应用私聊）代码还在，但**需要企业账号**。
> 个人「豆包账号」调 `tenant_access_token` 会返回 `21001 Access denied`，
> 所以当前没启用。将来换成企业账号，填三个 Secret 就能用。

## 几个踩过的坑

**番名用有辨识度的两三个字。** 站内搜索是子串匹配，太短会搜出一堆无关的。
搜不到时机器人会提示你换写法，试试日文原名或罗马音。

**繁简不通。** 搜「学生会」可能 0 条、搜「Seitokai」50 条 —— 脚本内置了繁简转换，
并且「最新流 + 关键词搜索」双路抓取，空结果不当结论。

**主域名 `share.acgnx.se` 在国内被 DNS 污染**（解析到 Facebook 的 IP）。
脚本用的是镜像 `share.acgnx.cc`，走 Cloudflare，国内直连。

**RSS 没有反爬挑战**（网页版才有），所以脚本全走 RSS 接口：

- `/rss.xml` 只覆盖最近约 12 小时
- `/topics/rss/rss.xml?keyword=xxx` 覆盖该番整季

## 运行成本

GitHub Actions 对公开仓库不限分钟数，所以**零成本**。
改成私有仓库的话免费额度只有 2000 分钟/月，每 5 分钟跑一次要 8640 分钟，会超支。

| 文件 | 作用 |

| `.github/workflows/watch.yml` | 被 Cloudflare 触发，每轮检查一次 |
| `.github/workflows/add-rule.yml` | Actions 页面手动加番 |
| `.github/workflows/issue-rule.yml` | 发 Issue 加番 / 删番 / 查列表 |
| `.github/ISSUE_TEMPLATE/` | 手机上「新建议题」时让你选的模板，标题会自动预填 |
| `cloudflare-cron/` | 不含密钥的定时器 Worker 模板和部署步骤 |

> 这类故障全是静默的：工作流名字会变成文件路径、或者完全没反应，日志里什么都看不到。
> 光看「代码跑通了」不算数。

## 如果哪天要重装

1. 建一个**公开**空仓库（不勾 README / gitignore / license）
2. 把本目录所有文件传上去，包括 `.github` 和 `state.json`
3. 仓库 `Settings` → `Secrets and variables` → `Actions` → New repository secret：
   - `ACGNX_WEBHOOK_URL` = 飞书群机器人的 Webhook 地址
4. 建 Cloudflare Worker（[`cloudflare-cron/README.md`](cloudflare-cron/README.md) 里有完整步骤）：
   - 部署 `worker.js`（有 `[triggers] crons = ["*/5 * * * *"]`）
   - 变量：`GH_TOKEN`（仅目标仓库的 Actions: Read and write）、
     `REPO`（填仓库全名）；模板不开放网页触发入口
5. 在 Cloudflare 里点「获取 Token」确认密钥填对了

Secret 是给工作流用的，`config.json` 里不要填任何密钥 —— **这个仓库是公开的**。


## 开发验证与权限

Issue 加番、删番、选组仅接受仓库所有者操作，普通访客和 PR 评论不会执行规则管理。
三个修改配置/状态的工作流共用 `acgnx-state-writer` 并发组，检出最新 main 后执行。
GitHub 并发组不保证先进先出，高频操作时请确认各次运行结果。

`--from-episode N` 会保存为规则的 `from_episode`，后续轮询也跳过更早的集数；
跨过 N 的合集和无法解析集数的资源仍会保留。已有规则可手工加入该字段。

```bash
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python check_workflows.py --require-bash
```

工作流检查同时验证 YAML 与 Bash 脚本语法，需要可用的 Bash。
PR 自动执行上述检查，不读取推送密钥、不发送消息。
Worker 模板是新增参考实现，未自动替换现有 Cloudflare 部署。

## 第一批可靠性改进

- 加番时的历史通知如果发送失败，会作为待发送消息保存在 `state.json` 的
  `pending_notifications`，由定时检测继续重试；成功后移除。这里保存消息内容，不保存渠道密钥。
  删除规则时也会取消它尚未送达的通知。`backfill=none` 仍只发送加番确认，不发送历史磁力。
- Issue 明确显示脚本执行是否成功。规则已保存但消息尚未送达时，会提示“通知待重试”，
  不把接口失败当成已送达；脚本异常和无搜索结果也不会再显示成添加成功。
- 序号选组绑定机器人评论中保存的原清单。搜索排名变化不会改变序号的含义；
  回复“刷新”可重新获取清单。旧 Issue 如果没有清单快照，会先刷新并请你重新选，不猜测原序号。
- Actions 的 `all/latest/none`、季号和起始集数在“直接加番”和“转 Issue 选组”两条路径保留一致。
  Issue 正文可使用 `### 推哪些` 字段，值填 `all`、`latest` 或 `none`；省略时仍为 `all`。
- `--list` 和 `--dry-run` 不修改持久状态；标题解析诊断由正式执行入口统一合并保存。

命令行按序号选组时也必须使用原快照：

```bash
python add_rule.py demo --survey --snapshot-out survey.json
python add_rule.py demo --pick 2 --snapshot-file survey.json --yes --no-push
```

这批改进没有改变已有规则和去重键。外部消息发送与远端状态提交仍不是同一个事务，
进程中断或 Git 提交失败后的恢复属于后续改进范围，不能保证任意故障下绝对不重发。
