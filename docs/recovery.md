# 状态与故障恢复

## 文件职责

`config.json` 保存规则，`state.json` 保存版本化基线、待发送消息、检查状态与最近送达信息。
`state.backup.json` 保存上一次有效主状态。云端工作流会一并提交主状态和备份。

旧状态首次读入会在内存迁移到 `state_version=1`，保留已有规则 ID 和两段/三段去重键；只有正式保存时才落盘。组名等价时复用旧键，不删除旧历史。

## 损坏与缺失

1. 主状态损坏/缺失、备份有效：读取备份并记录恢复警告；只查看时不覆盖文件，正式运行后保存恢复状态。
2. 主状态和备份均损坏：程序停止，不静默建立空基线。请从 Git 历史恢复最近一次成功运行的状态。
3. 两个文件都不存在：按新部署处理。已有项目不要同时删除这两个文件，否则可能重新推送历史。

手动恢复前先保存现有文件，暂停外部定时器，确认要恢复的提交日期与规则版本一致。PowerShell 示例：

```powershell
Copy-Item -LiteralPath .\state.json -Destination .\state-before-recovery.json
Copy-Item -LiteralPath .\state.backup.json -Destination .\state.json
python add_rule.py --validate
python acgnx_watch.py --once --dry-run
```

若主状态不存在，跳过第一条复制。检查输出后再恢复定时器。备份可能比主状态少一轮数据，恢复后仍有少量重复窗口。

## 抓取失败

有效空 RSS 与网络/解析失败分开记录。部分源成功显示 partial；全部源失败不推进初始化或集数基线，单轮命令返回非零退出码，状态保存步骤仍会执行。

默认连续失败 3 次发送一次告警；持续失败不每轮刷屏，恢复后发送一次恢复提示。可在 settings 设置 `failure_alert_after`。推送服务本身不可用时，告警也进入待发送队列。

## 消息发送与 Git 保存

回溯通知和正常单集均按任务内容生成稳定队列键。基线与待发送任务一并保存后才发送，逐条确认成功并立即保存收据；失败保留原消息重试，即使资源已经退出 RSS 也不依赖重新抓到它。基线表示已纳入处理，并不等于已送达，待重试数量及最近送达信息才反映发送结果。Git 提交失败会使 Actions 失败并保留可查日志。

**外部推送与远端 Git 提交不是原子事务。** 逐条保存缩小了进程中断的重复窗口，但服务收到消息到本地收据保存之间，以及本地状态到远端 Git 提交之间，仍有重复窗口。本项目不承诺 exactly-once。遇到这种情况先恢复状态提交，不要反复重跑旧任务。

`--reset-state` 是明确重建基线的操作，会同时重置主状态与备份。仅在理解后果时使用，不用它来处理普通重复推送问题。
