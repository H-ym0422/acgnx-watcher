# 自然语言标题

关键词 RSS 搜索现优先使用 `/rss.xml?keyword=…`。定时监听、资源查询、字幕组选组及历史补抓共用同一适配器。返回值必须是有效 RSS/Atom；HTML 错误页或验证页会触发镜像与旧入口回退，有效空 RSS 则作为正常零结果。选组时所有搜索失败会明确报错，不生成无资源结论或新规则。

“搜索异常/恢复”描述关键词搜索状态；最新资源流可用时通知会明确说明。最新流只有有限的近期覆盖，不能代替关键词搜索。恢复后自动继续检查，不需重建订阅。

新建 Issue，选择“自然语言请求”或空白 Issue，把完整要求写在标题，正文可以留空。

| 标题例子 | 结果 |
|---|---|
| 给我找药屋少女的呢喃第三季第三集之后的资源，字幕组为喵萌奶茶屋 | 只查一次，第 3 集及以后 |
| 给我找药屋少女的呢喃第三季第三集的资源，字幕组为喵萌奶茶屋 | 只查第 3 集 |
| 给我找药屋少女的呢喃第三季第三至第五集的资源 | 查询 3—5 集，任意组 |
| 帮我追药屋少女的呢喃第三季，从第三集起，字幕组为喵萌奶茶屋 | 持续监听，回溯第 3 集及以后 |
| 帮我追示例动画，只推最新一集，字幕组为喵萌奶茶屋 | 回溯最新集，以后持续监听 |
| 帮我追示例动画，不补旧集，字幕组为喵萌奶茶屋 | 跳过旧集，以后持续监听 |
| 帮我追示例动画，字幕组为喵萌奶茶屋，不兜底 | 只接收该组，其他组不补 |
| 帮我暂停药屋少女的呢喃第三季 | 暂停唯一匹配的规则 |
| 帮我恢复药屋少女的呢喃第三季 | 恢复唯一匹配的规则 |
| 帮我删除药屋少女的呢喃第三季 | 删除唯一匹配的规则 |
| 帮我把药屋少女的呢喃第三季的字幕组改为喵萌奶茶屋 | 修改字幕组并保留规则 ID |
| 我的追番列表 | 查看追番规则 |

中文数字和阿拉伯数字都可以。“第三集之后”“从第三集起”均包含第 3 集；不包含时写“从第四集起”。
查询只在 Issue 回复资源，**不添加订阅、不修改推送历史、不发送飞书**。结果受 RSS 近期窗口限制；没找到不代表字幕组停更。合集按交集返回，可能包含范围外集数。季度无法确认的资源会保守排除。

“帮我追”“订阅”“加入监听”会长期保存规则。未写回溯方式时沿用 all；未写字幕组时先列清单，再回复序号或组名。除“不兜底”外，继续按每集首次观察到其他组资源后等待 7 天的策略补发。

使用本地规则解析常见中文表达，不需要额外模型或密钥，也不承诺理解任意长句。每个 Issue 只写一个操作，条件用逗号分隔；识别结果会显示在回复开头。多个规则匹配时拒绝操作，请改用列表中的唯一规则 ID。标题和正文条件冲突时拒绝修改；自然语言查询的条件请完整写在标题。

# 使用与规则管理

## 静默删除

成功删除追番不发送飞书提醒，也不追加 Issue 成功评论。删除记录的永久清理可通过仓库 Secret `ACGNX_ISSUE_DELETE_TOKEN` 启用；令牌必须代表个人仓库的所有者。公开仓库可使用 classic 令牌的 `public_repo` 权限；此权限不支持限定单个仓库，不要误选整个 `repo` 或 `delete_repo`。GitHub 普通工作流令牌不足以代表个人仓库所有者执行永久删除。

永久清理仅针对当前已成功完成、已保存的删除 Issue，不扫描或删除无关 Issue，也不在规则删除失败、状态未保存时清理记录。未配置所有者令牌或永久清理失败时，删除记录仅静默关闭，诊断信息在 Actions 日志中查看。

当前飞书 Webhook 历史消息无法由项目自动撤回：没有保存可用的消息 ID，也没有应用/用户撤回授权。删除追番仅停止后续推送并清除待发送任务；飞书中已经送达的消息需在客户端处理。要支持应用消息撤回，需要另行配置飞书应用权限与可追溯的消息 ID，且仍受飞书时限及身份限制。

## 操作记录与列表显示

“我的番剧.md”默认隐藏内部编号；删除链接自动携带规则身份，确认标题使用番名、季度和字幕组。成功删除后，程序重新生成列表，已删除的行自动移除。

GitHub Issues 中的加番、删除、查询等属于操作记录，不等于当前追番列表。加番、查询等处理成功且保存完成后自动关闭归档；删除操作则按上述令牌配置永久清理或静默关闭。等待选组和执行失败的 Issue 保持打开。已关闭记录仍可供查阅，日常在 Open 列表中不会继续堆积。

## 点击确认删除

打开仓库的“我的番剧.md”，在要删除的那一行点击“删除”。确认页会自动填入番名、季度、字幕组和校验信息；核对后勾选“我确认删除这条追番规则，并清理其待发送消息和去重记录”，然后提交。

提交前不执行删除；不想删时关闭页面即可。每个入口绑定唯一规则 ID，只删除对应行。若规则已修改、已删除，或确认内容不匹配，会拒绝执行，需刷新列表重新进入。不要修改自动填入的对象、确认标题 或校验信息。此入口由 GitHub Actions 生成，本地生成时需提供 GITHUB_REPOSITORY 环境变量。

GitHub Markdown 文档本身不能弹出交互式确认框，因此通过独立确认页完成勾选；旧指令仍可使用。标题支持“删除：番名”和嵌套的模板前缀；同名规则存在多条时会列出候选，不能仅凭番名删除。

“字幕格式为……”暂不属于支持的自然语言筛选条件，程序会拒绝该请求，避免把条件拼入番名。选组清单仍会逐集列出可选字幕类型。

## 手机入口

在 GitHub 仓库创建 Issue，只有仓库所有者的指令会执行。

| 标题 | 行为 |
|---|---|
| `加番 番名` | 列出字幕组，回复原清单序号或完整组名后添加 |
| `列表` | 生成包含番名、暂停状态、检查/推送记录的清单 |
| `暂停 规则ID` | 停止该规则，保留去重记录，取消尚未发送的历史通知 |
| `恢复 规则ID` | 恢复监听，保留去重记录 |
| `修改 规则ID` | 修改指定字段，不重建规则 ID |
| `删番 规则ID` | 删除规则，取消待发送通知并清理该规则基线 |

选组清单以机器人评论中的快照为准。回复“刷新”会生成新清单；旧 Issue 没有快照时会要求重新选一次。不要编辑或复制评论内的隐藏快照。

## 添加或修改的正文

只写需要设置的项目。加番模板有可选输入框，也可手动写：

```text
### 字幕组
喵萌奶茶屋,北宇治字幕组

### 第几季
2

### 只要第几集之后
49

### 推哪些
latest
```

字幕组填“任意”表示不限定。季号 0 表示不限定。指定季号后，优先采用标题明确季号；标题缺少季号时，可使用本番明确标注的 `03(51)` 等对应关系识别累计集号，不靠猜测每季有 12/24 集。季度与集号映射会保存，后续搜索也可继续使用。

如果证据不足，该规则清单会显示 `needs_confirmation` 和“需确认季度”的集号，相关集号的兜底也会暂缓，避免把未识别的指定组误当成未发布。可以在“修改 规则ID”的 Issue 正文填写以下项目（可单独填写）：

```text
### 季内起始总集号
49

### 未标季度
不允许
```

起始总集号 49 表示本季第 1 集对应累计第 49 集，按此转换累计编号；0 表示未指定。若你确认本规则的未标季度资源都可接收，可将“未标季度”改为“允许”，这是显式放宽，仍存在混季风险；明确标注其他季度的资源始终排除。也可在 config.json 对应规则设置 `season_start_episode` 和 `allow_unmarked_season`。

起始集数对未来检测与待重试单集也有效；已知累计／季内映射时会一并转换起点，未知集数和覆盖起点的合集仍保留。修改字幕组时自动生成的名称会同步更新，自定义名称保留。直接在配置中暂停或删除规则，下一轮也会取消其待发送消息；当前 Webhook 渠道不会自动撤回已送出的消息。

`推哪些` 仅用于添加时的历史回溯：`all` 全部历史（保持原默认），`latest` 最新一集，`none` 不发历史资源、只发加番确认。修改规则不会自动再发全部历史。起始集数变化会取消低于起点的待重试单集，仍符合条件的单集保留；关闭兜底会取消已排队的兜底。无法安全拆分的过期历史汇总通知会取消。

多个指定组可分别推同一集。配置了指定组并启用兜底时，其他组先发布只开始计时，不立即推送：从首次观察到该集其他组资源起等待完整 7 天（168 小时），每条规则、每一集独立计时，不使用资源标注的发布日期倒推。升级前未记录等待时间的资源从升级后首次观察开始计时。

等待时间和候选资源保存在状态中，重启不会重置计时，资源退出 RSS 后仍可在期满时使用。期间检测到任一指定组版本或已有该集指定组历史记录，就取消该集的普通兜底。等待满 7 天仍未检测到指定组时，才允许选一份最优其他组资源；这不代表指定组停更，指定组后来发布仍会提醒。

加番历史回溯也遵守等待期；`none` 不会在一周后补发原本跳过的历史，`latest` 不会变成延迟发送全部历史。未指定字幕组的规则不需要等待；关闭兜底的规则始终只收指定组。

## 命令行

```bash
python add_rule.py --validate
python add_rule.py --list
python add_rule.py --pause demo-rule --no-push
python add_rule.py --resume demo-rule --no-push
python add_rule.py --edit demo-rule --group 喵萌奶茶屋 --from-episode 49 --no-push
python add_rule.py --edit demo-rule --season-start-episode 49 --strict-season --no-push
python add_rule.py 番名 --survey --snapshot-out survey.json
python add_rule.py 番名 --pick 2 --snapshot-file survey.json --yes --no-push
python acgnx_watch.py --list
python acgnx_watch.py --once --dry-run
```

`--list`/`--dry-run` 不修改去重状态，dry-run 不发送待重试消息。日志仍可能写入 logs。配置示例见根目录 `config.example.json`；不要用示例覆盖现有个人规则。

## 每集字幕形式

选组清单按字幕组分别列出“集数 → 字幕形式”，不再只给一组总括类型。例如：

```text
01~03、05、08~10 简日双语
04、06~07 简繁内封
11 未标注，请查看发布说明
```

连续集号自动合并，缺集保留间断；合集范围也可参与合并。同一集的多种可选版本分别列出，不表示每个资源都同时带这些字幕。不同字幕组不混为一条汇总。

加番回溯消息的汇总对应实际选中的资源，每条磁力旁也标注字幕类型；只回溯最新一集时仅显示该资源的类型。未知格式明确提示查看发布说明，不根据其他集猜测，也不推断其为生肉。类型来自发布标题，程序不会下载资源核验内部字幕。

## 看懂清单与消息

- 已记录到：去重基线，不代表每条历史通知已送达。
- 最近成功推送：从本版本开始采集，旧数据不会伪造历史时间。
- 待重试：接口未确认成功的通知数量，下一轮会再次尝试。
- 指定组/兜底：显示最近单集消息的选择结果；集数不确定会明确提示。
- 未标字幕形式不能推断为生肉；搜索最大集号不等于全季总集数。

新规则使用 UUID，旧规则的 ID 保持原样。重复添加相同关键词、季号和字幕组不会创建新规则；不同季号或不同组可分开配置。近义番名仍需手工检查，程序不保证识别所有译名的语义等价。

## 资源识别与单部番状态

明确的漫画、小说、电子书分类、书籍卷号和资源格式会被排除，已有等待缓存也会重新检查；动画标题本身含“漫画”二字不作为排除依据。同一集的明确季内／累计对应关系统一用于去重、等待与历史键兼容，旧历史键保留。指定组的合集或多个连续范围覆盖某单集时，会阻止该单集的普通兜底。

清单逐条显示规则抓取状态。某部番所有搜索持续失败仍会告警，其他来源成功不会掩盖它。网站整体不可用时只发一条总告警，不重复发各部番告警；整体恢复也只发一条，部分恢复会列出仍异常的番剧。同轮多部番的状态变化合并为一条通知，持续故障不重复提醒。有效空 RSS 不算网络故障。标题缺失、分类错误或无法建立编号关系时仍可能需要人工确认。

## 配置永久清理令牌

1. 以仓库所有者登录 GitHub，打开 Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)。
2. 公开仓库仅勾选 `repo` 下的 `public_repo` 子项。选择到期时间；若选择 No expiration，令牌会一直有效直到手动撤销。
3. 生成并复制令牌，在目标仓库 Settings → Secrets and variables → Actions → New repository secret 中保存为 `ACGNX_ISSUE_DELETE_TOKEN`。不要将令牌放进 Issue、README、截图或公开配置。
4. 无需重启。下次成功保存的删除操作自动使用该令牌；添加 Secret 不会自动清理已有历史 Issue。

本仓库已于 2026-10-19 完成所有者身份及真实永久删除验证。一次性清理固定的 61 条历史记录，保留“追番｜FX战士久留美”“追番｜某暗部的少女共栖”“追番｜学生会有洞”三条入口。这些 Issue 不自动同步订阅变更，日常管理仍从 [我的番剧](../我的番剧.md) 进入；不要仅关闭或删除追番 Issue 来取消实际订阅。

飞书自定义 Webhook 不能自行撤回消息。群主或管理员可在客户端按权限和时限撤回；只在自己客户端删除并不代表群内撤回。当前未部署云端或本地界面自动化，不能仅靠现有 Webhook 地址开启这类清理。

## 推送消息标题

新集资源沿用 `settings.title_prefix`，默认“【新番速递】”。更优版本和修正版使用“【资源更新】”，保留“（更优版本）”或“（修正版）”标记；整体、单部番及合并的抓取异常/恢复使用“【运行提醒】”。这两类前缀不随普通新集的 `title_prefix` 改变。已发送的旧消息不会自动改名。
